   - 5-hour limit ≥ 85 % → no work. `ScheduleWakeup` for the reset: `delaySeconds` = seconds until `resetsAt` + 120, at most 3600; `noop: true`.
2. **One work block** = the first unticked Queue item, or one batch of it; ≤ ~30 tool calls of your own. New PDFs (item A) always go first. Subagents only while the 5-hour limit is ≤ 65 %: at most 2 at a time, in the background; check usage again each time one returns. While agents run: `ScheduleWakeup` 1800 s as fallback.
3. **Save** — tick or annotate the Queue item, add one Log line, `git add` only the files you changed, commit (never push, stash, reset or switch branch: other sessions edit this repo too).
4. `ScheduleWakeup` 60 s, `noop: false` → next iteration.

## 2. Rules
- Read once per session: `CLAUDE.md`, `notes/claude-notes.md`, the header of `Literature/review-matrix.md` (conventions: status, CN/INT, †, `~`, `n/r`, DOD formula, Zotero tags).
- **Sources:** every DOI is checked with `PYTHONIOENCODING=utf-8 py tools/lit.py <dois.txt> <out.json>` (Crossref + Semantic Scholar; one DOI per line; work files in the session scratchpad). Bibliographic data never from memory. Numbers only from text actually read, with location (`abs`, `Fig. 3b`, `Tab. 1`, `SI Fig. S4`, `p. 4`); figure read-offs `~`; own calculations `(calc)`; numbers from search-engine excerpts `†`; unknown `n/r`. No quotes over ~10 words. Surnames only.
- **CN tag:** corresponding author's institution in mainland China/HK/Macau = `CN`, otherwise `INT`, undeterminable = `origin-unknown`.
- **Zotero** (tools deferred: load with ToolSearch; current state via `curl.exe "http://localhost:23119/api/users/0/items/top?limit=100&start=0&format=json"`): add by DOI with `if_exists: "file"`, `attach_mode: "none"`, into the matching chapter collection; tags `lr-<section>`, one of `full-text-read | abstract-only | needs-access`, one of `CN | INT | origin-unknown`, one of `rel-high | rel-medium`; one note "Lit review §x" with 3 lines (what / numbers with location / relevance). When a status changes: swap the tag (`zotero_batch_update` with `add_tags` + `remove_tags`) and append one line to the note. No deletions, no attachment changes, leave item DML59VLW alone. If Zotero is unreachable: do the matrix work, log "Zotero pending: <DOIs>", go on.
- **Files you may change:** `Literature/review-matrix.md` · the gap list in `Literature/triage.md` · this file · new scripts in `tools/` · new files under `Thesis Proposal/drafts/` (each starts with the line "DRAFT — generated by the night loop, not reviewed") · `Thesis Proposal/proposal/ref/refs.bib` only via `powershell -ExecutionPolicy Bypass -File tools\zotero2bib.ps1`. Everything else is read-only: `COMSOL/`, `notes/parameters.md`, `notes/progress.md`, `Literature/paper-summary.md`, the proposal `.tex` files, `proposal-plan.md`, `outline.md`, `CLAUDE.md`.
- **Confidential:** the group manuscript and SI in `Literature/` — never search for them or quote them externally. No personal data in web requests.
- **Never wait for the student.** If something needs a decision, take the conservative option, note it under "For the student" and go on. Avoid anything that could raise a permission prompt: no installs, no pushes, no writes outside the repo and the session scratchpad.
- **Keep your own context small.** Long texts are read by subagents (≤ 3 PDFs or one search topic each); each writes a result file to the scratchpad and returns ≤ 150 words; you merge. Tell every agent the Sources rules above.
- Network: the Semantic Scholar *search* API mostly answers 429 → WebSearch + Crossref title search (`https://api.crossref.org/works?rows=5&query.bibliographic=<title>`). RSC, MDPI, Wiley and Cell pages often refuse automated fetches → for open-access papers try Europe PMC full text. OpenAlex is unreachable.
